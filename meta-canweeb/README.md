# meta-canweeb

Yocto layer that builds a robotics-optimized Linux image for Raspberry Pi with CanWeeb pre-installed.

## What this layer provides

- **CanWeeb runtime** pre-installed and enabled as a systemd service
- **PREEMPT_RT** full preemption kernel configuration
- **Robotics-optimized kernel** (cpufreq performance, CAN bus, GPIO, USB serial, rotary encoder support)
- **IRQ affinity** setup (CPU 0-1 for OS, CPU 2-3 reserved for CanWeeb real-time tasks)
- **sysctl / ulimit** tuning for low-latency network and memory locking
- **Parent/child node role selection** at first boot via SD card files
- **python3-websocket-client** for Python visualizer examples

## Quick start

### Requirements

- Ubuntu 22.04 or 24.04 (recommended for Yocto scarthgap)
- Packages: `git python3 python3-pip gcc g++ make diffstat unzip texinfo chrpath cpio file wget xz-utils`
- At least 80 GB free disk space
- At least 8 GB RAM

Install dependencies:
```bash
sudo apt-get install -y \
    gawk wget git diffstat unzip texinfo gcc build-essential \
    chrpath socat cpio python3 python3-pip python3-pexpect \
    xz-utils debianutils iputils-ping python3-git python3-jinja2 \
    libegl1-mesa libsdl1.2-dev pylint xterm python3-subunit mesa-common-dev \
    zstd liblz4-tool file locales libacl1
```

### Build

```bash
# From the CanWeeb repository root:
./build-image.sh

# With options:
./build-image.sh --machine raspberrypi4-64 --role parent --jobs 8

# Clean build:
./build-image.sh --clean
```

Supported `--machine` values:
- `raspberrypi4-64` (recommended, quad-core 64bit)
- `raspberrypi3-64`
- `raspberrypi4`
- `raspberrypi3`

### Flash to SD card

After the build finishes, the SD card image is in:
```
build/tmp/deploy/images/<MACHINE>/canweeb-image-<MACHINE>.wic.bz2
```

Flash with bmaptool (fast):
```bash
sudo bmaptool copy build/tmp/deploy/images/raspberrypi4-64/canweeb-image-raspberrypi4-64.wic.bz2 /dev/sdX
```

Or with dd:
```bash
bzcat canweeb-image-raspberrypi4-64.wic.bz2 | sudo dd of=/dev/sdX bs=4M conv=fsync status=progress
```

### Set node role

After flashing, mount the SD card boot partition and write:

```bash
# Set as parent node
echo parent > /boot/canweeb-role

# Set as child node
echo child > /boot/canweeb-role

# Optional: set a custom node ID
echo my-robot-parent > /boot/canweeb-node-id

# Optional: set peer address (child points to parent)
echo 192.168.1.100:7002 > /boot/canweeb-peer-addr
```

On first boot, `canweeb-init.service` reads these files and writes `/etc/canweeb/config.toml` accordingly, then starts `canweeb.service`.

If none of these files exist, the node defaults to `parent` role.

## CPU layout on Raspberry Pi 4

| CPU | Role |
|-----|------|
| CPU 0 | OS, IRQs, kernel threads |
| CPU 1 | OS, IRQs, kernel threads |
| CPU 2 | CanWeeb (FIFO RT, isolated) |
| CPU 3 | CanWeeb (FIFO RT, isolated) |

IRQ affinity is set by `irq-affinity.service` at boot.

## Rebuild after code changes

Any time you change the CanWeeb source, just run:

```bash
./build-image.sh
```

The script automatically re-packages the source into a tarball and triggers bitbake.
For an incremental rebuild (much faster after the first full build):

```bash
./build-image.sh
# bitbake will only rebuild changed recipes
```

To force a full clean rebuild:

```bash
./build-image.sh --clean
```

## Kernel configuration

Two `.cfg` fragments are applied on top of the default RPi kernel config:

- **`preempt-rt.cfg`** — enables `CONFIG_PREEMPT_RT`, 1000 Hz timer, IRQ threading, CPU isolation
- **`canweeb-robot.cfg`** — GPIO, I2C, SPI, USB serial, CAN bus, rotary encoder, cpufreq performance, cgroups, watchdog

## Adding the layer to an existing Yocto setup

Add to your `bblayers.conf`:
```
${CANWEEBROOT}/meta-canweeb \
```

Add to your `local.conf`:
```bitbake
IMAGE_INSTALL:append = " canweeb canweeb-init robotics-tweaks"
```

And apply the kernel fragments via:
```bitbake
# already done by linux-raspberrypi_%.bbappend inside this layer
```
